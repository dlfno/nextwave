# Nextwave hackathon demo

## One-command container demo

```sh
docker compose -f compose.demo.yaml up --build
```

Open `http://localhost:4000`. The stack starts PostgreSQL, the separate NubeVia
HTTP/UCP merchant, the Express API, and the Angular SSR application. It applies
migrations and creates persistent development ES256 keys for both trusted-surface
and merchant signatures. On the first launch it also creates the judge accounts
below. Later container restarts preserve purchases until an explicit reset.

## Judge accounts

All three accounts use `nextwave-demo-2026` unless `DEMO_ACCOUNT_PASSWORD` is set
before startup.

| Role | Email |
| --- | --- |
| Human | `marta@nextwave.demo` |
| Merchant operator | `merchant@nextwave.demo` |
| Auditor | `auditor@nextwave.demo` |

The password is a public demo credential, not a production secret.

The signing keys generated by the container entrypoint are intentionally ephemeral
and suitable only for the hackathon demo. Supply managed keys through
`MANDATE_SIGNING_PRIVATE_JWK` and `VUELAYA_SIGNING_PRIVATE_JWK` outside the demo.

## Trial-by-fire browser suite

From `front/`:

```sh
npx playwright install chromium
npm run e2e
```

The suite covers the $130 happy path, checkout-specific human approval, $300
denial, live revocation, human/merchant/auditor evidence, disputes, and desktop and
mobile viewport fit. It uses the deterministic presentation routes, so it does not
require a database and remains reliable during judging rehearsals.

To run the persisted rehearsal against the container stack:

```sh
./scripts/demo-reset.sh
cd front
PERSISTED_DEMO=true PLAYWRIGHT_BASE_URL=http://localhost:4000 npm run e2e:persisted
```

## Five-minute judge script

1. **0:00 — Authority:** Log in as Marta. Create the complete MEX → COR request,
   review the structured mandate, and authorize it.
2. **1:00 — Deterministic denial:** Start discovery and select the $300 offer.
   Point out `AMOUNT_EXCEEDS_MANDATE` and the missing payment action.
3. **1:40 — Human approval:** Return to offers, select $130, approve the exact
   checkout, and complete payment. Open Activity to show the receipt and audit chain.
4. **3:00 — Role evidence:** Copy the transaction and attempt URLs. Log in as the
   merchant operator and auditor in separate private windows to show scoped evidence.
5. **4:00 — Trial by fire:** Create and authorize a fresh mandate, revoke it, then
   attempt the otherwise-valid $130 checkout. Show `MANDATE_REVOKED`.
6. **4:40 — Dispute:** Open the completed transaction, dispute it, and show the
   frozen reconstruction bundle.

## Operations and recovery

Check both process health and dependency readiness:

```sh
./scripts/demo-status.sh
```

Reset only user-owned demo state while preserving the catalog and migrations:

```sh
./scripts/demo-reset.sh
```

If a rehearsal fails:

1. Run `docker compose -f compose.demo.yaml ps` and `./scripts/demo-status.sh`.
2. Inspect `docker compose -f compose.demo.yaml logs --tail=100 api web postgres nubevia`.
3. Run `./scripts/demo-reset.sh`, reload the browser, and sign in again.
4. If readiness remains red, restart with
   `docker compose -f compose.demo.yaml up -d --build`.

Do not use `docker compose down -v` during judging; it removes the database volume.
